# A 股 ETF 量化研究与回测平台

# 总体架构 PRD V0.1

## 1. 产品概述

### 1.1 产品定位

构建一个本地运行的 A 股 ETF 量化研究与回测平台（Quant Research Workspace）。

平台以 TypeScript 为主要开发语言，通过统一的 Quant SDK 提供数据访问、特征计算、技术指标、统计分析和策略回测能力。

用户通过 Codex 编写 Research（研究项目）和 Strategy（策略项目），在 Web 界面中调整参数、执行项目、查看结果和验证研究结论。

平台不负责自动生成研究逻辑，也不要求用户开发独立的前端页面。

### 1.2 核心使用方式

整个系统围绕以下工作流程：

1. 平台提前采集和准备 ETF 数据。
2. 验证行情数据，计算并保存每日公共特征。
3. 用户通过 Codex 编写 Research 或 Strategy 项目。
4. 项目声明所需数据、可调整参数和结果展示内容。
5. 用户在 Web 界面调整参数并运行项目。
6. 平台检查数据是否满足运行要求。
7. Runtime 执行项目并调用 Quant SDK。
8. 保存运行参数、日志和计算结果。
9. Web 界面自动展示概览统计、图表和表格。
10. 用户调整参数、重复运行、对比结果，持续验证研究结论。

### 1.3 产品目标

- 统一管理 A 股 ETF 行情和相关基础数据。
- 提前准备公共数据，避免每个研究项目重复采集。
- 统一公共特征和技术指标的计算口径。
- 通过 SDK 降低研究和策略的开发成本。
- 支持 Codex 快速创建和修改研究项目。
- 支持在线参数调整和多次实验。
- 自动生成统计、图表和表格展示。
- 支持历史研究结果追踪和对比。
- 提供完整的日 K 级别回测能力。

## 2. 产品范围

### 2.1 研究范围

| 项目     | 范围                           |
| -------- | ------------------------------ |
| 市场     | A 股 ETF                       |
| 行情周期 | 日 K                           |
| 行情口径 | 前复权                         |
| 数据范围 | 全部纳入管理的 ETF             |
| 研究类型 | 定量研究、横截面分析、因子研究 |
| 策略类型 | 用户自定义策略                 |
| 回测方式 | 历史数据模拟，不涉及实盘       |
| 运行方式 | 本地单机运行                   |
| 开发语言 | TypeScript                     |

### 2.2 回测基础约束

- 只支持做多，不支持杠杆和融资。
- 按日 K 收盘价模拟成交。
- 策略可以决定买入金额或数量。
- 资金不足时按订单优先级处理，不足订单跳过。
- 无效交易单位拒绝执行。
- FIFO 成本核算。
- 公司行为进行检测和提示，暂不完整模拟。
- 支持单 ETF 和多 ETF 回测。

### 2.3 非目标

V0.1 不建设：

- 实盘交易和券商交易接口。
- 高频交易和分钟级回测。
- 多市场统一量化平台。
- 在线多人协作和云端部署。
- 在线 IDE 和代码编辑器。
- AI 自动生成研究结论。
- 每个研究项目独立开发前端页面。
- 复杂的分布式计算和多节点任务调度。

## 4. Data Engine：数据管理

### 4.1 模块定位

Data Engine 负责平台基础数据的完整生命周期。

数据采用提前采集与按需补齐相结合的方式。

Research / Strategy 不直接负责爬虫，而是通过统一数据接口使用已经准备好的数据。

### 4.2 数据分类

| 数据           | 数据口径     | 存储策略     |
| -------------- | ------------ | ------------ |
| ETF 基础信息   | 最新基础信息 | 定期更新     |
| ETF 日 K       | 前复权行情   | 保存历史数据 |
| ETF 规模       | 最新基金规模 | 最新快照     |
| ETF 溢价率     | 最新溢价率   | 最新快照     |
| ETF 持仓       | 最新一期持仓 | 最新快照     |
| 行业分类       | 最新分类数据 | 最新快照     |
| ETF 与指数关联 | 当前关联关系 | 最新数据     |

注意：

1. Kline 表只保存前复权行情，不建设 KlineRaw。
2. 最新规模、溢价率、持仓和行业分类不回填历史日期。
3. 不允许使用最新快照伪造历史数据。
4. 原始数据来源、采集时间和验证状态应可追踪。

### 4.3 数据采集能力

需要支持：

- 首次全量采集。
- 每日增量采集。
- 指定 ETF 采集。
- 指定日期范围补齐。
- 历史数据重新采集。
- 采集任务状态和日志记录。

### 4.4 数据验证

至少检查：

- 数据是否重复。
- 日期是否缺失。
- OHLC 数据是否符合基本价格关系。
- 成交量和成交额是否异常。
- 数据字段是否为空。
- 数据是否发生历史修订。

发现异常时记录验证结果，不应直接将未经验证的数据提供给研究项目。

### 4.5 数据修复

当发现历史行情发生修订时：

1. 重新采集受影响的行情。
2. 验证新行情。
3. 更新数据库。
4. 标记受影响的公共特征。
5. 触发对应日期及后续依赖日期的特征重算。
6. 记录数据修订历史。

### 4.6 数据访问原则

通过 Data API 统一访问数据。

当研究项目请求的数据不存在时：

1. 检查本地缓存。
2. 判断是否可以补齐。
3. 必要时触发采集任务。
4. 完成数据验证和存储。
5. 返回可用数据。

耗时的数据准备不应阻塞 HTTP 请求。

## 5. Feature Engine：公共特征计算

### 5.1 模块定位

Feature Engine 负责计算所有 ETF 共用的每日基础特征。

它与具体研究项目无关。

公共特征统一计算并持久化，避免不同 Research 重复计算相同内容。

### 5.2 特征范围

**行情特征**

- 开盘价、最高价、最低价、收盘价。
- 涨跌额、涨跌幅。
- 成交量、成交额。

**周期表现特征**

- 近 1 周、1 月、3 月、6 月收益。
- 今年以来收益。
- 近 1 年、3 年、5 年收益。
- 涨跌天数。
- 收益均值、中位数。
- 区间最大涨幅和最大跌幅。

**风险特征**

- 波动率。
- 最大回撤。
- 下行波动率。
- Sharpe Ratio。
- Sortino Ratio。
- Calmar Ratio。

**流动性特征**

- 成交额均值。
- 成交额中位数。
- 成交额变化。
- 成交活跃程度。

**横截面特征**

- RPS20。
- RPS60。
- RPS120。
- 对应周期排名。
- 横截面收益排名。

### 5.3 横截面计算规则

- 样本池为全部 ETF。
- 不按 ETF 分类拆分样本池。
- 不同周期独立判断历史样本是否充足。
- 历史不足的 ETF 只排除对应周期。
- Rank 1 表示收益最高。
- RPS 使用 0～100 百分制。
- 并列使用平均排名百分位。

### 5.4 不提前固化的内容

以下内容按研究需求计算：

- SMA / EMA。
- MACD。
- RSI。
- Bollinger Bands。
- ATR。
- 自定义因子。
- 未来收益标签。
- 策略信号。
- 研究结论。

技术指标统一通过 Indicator API 计算，保证参数、精度和空值规则一致。

### 5.5 计算任务

支持：

- 首次历史全量计算。
- 每日增量计算。
- 历史数据修订后的重算。
- 指定 ETF 重算。
- 指定日期范围重算。
- 计算版本管理。

## 6. Quant SDK：统一量化能力

### 6.1 模块定位

Quant SDK 是 Research / Strategy 唯一推荐的量化能力入口。

研究项目不直接操作 Prisma，不直接实现基础数据爬虫，也不重复建设公共计算能力。

### 6.2 SDK 模块

| API              | 职责                         |
| ---------------- | ---------------------------- |
| Data API         | ETF 信息、K 线和最新快照数据 |
| Feature API      | 读取每日公共特征             |
| Indicator API    | 计算技术指标                 |
| Statistics API   | 收益、风险、回撤等统计分析   |
| CrossSection API | 横截面分析、排名和分组       |
| Backtest API     | 策略回测                     |
| Result API       | 保存结构化研究结果           |

### 6.3 使用原则

- 所有数据访问通过 SDK。
- 行情数据统一使用前复权口径。
- 指标参数和计算规则统一。
- 统计口径统一。
- SDK 提供类型定义。
- 研究项目可以自由组合 SDK 能力。
- 不限制用户实现自定义研究算法。

示例：

```ts
const klines = await ctx.data.getKlines({
  codes: ["510300", "510500"],
  startDate: 20250101,
});

const rps = await ctx.features.get({
  codes: ["510300", "510500"],
  date: 20261127,
  fields: ["rps20", "rps60"],
});

const rsi = await ctx.indicators.rsi({
  values: closes,
  period: 14,
});
```

以上仅展示接口使用方式，具体 API 签名在 Quant SDK 技术设计中确定。

## 7. Project Engine：研究与策略项目

### 7.1 模块定位

Project Engine 负责发现、加载、校验和执行用户编写的项目。

项目由 Codex 或用户使用 TypeScript 编写。

平台不负责生成研究逻辑。

### 7.2 项目分类

```text
projects/
├── research/
│   ├── momentum/
│   │   ├── index.ts
│   │   └── README.md
│   │
│   └── rps-analysis/
│       ├── index.ts
│       └── README.md
│
└── strategies/
    └── weekly-momentum/
        ├── index.ts
        └── README.md
```

### 7.3 项目需要定义的内容

每个项目通过 `index.ts` 声明：

1. 项目 ID。
2. 项目名称。
3. 项目类型。
4. 数据需求。
5. 可调整参数。
6. 概览统计字段。
7. 图表定义。
8. 表格定义。
9. 项目执行入口。

### 7.4 项目执行约定

Research：

```ts
export default async function run(ctx: QuantContext, params: ResearchParams) {
  // 研究逻辑
}
```

Strategy：

```ts
export default async function run(ctx: QuantContext, params: StrategyParams) {
  // 策略逻辑与回测调用
}
```

具体类型和参数协议在 Project Engine 技术设计中确定。

### 7.5 项目自由度

项目可以自由决定：

- 研究什么问题。
- 使用哪些 ETF。
- 使用哪些行情字段。
- 使用哪些技术指标。
- 使用哪些统计方法。
- 如何计算因子。
- 如何组织研究逻辑。
- 展示哪些统计数据。
- 展示哪些图表。
- 展示哪些表格。

项目不需要开发独立前端页面。

## 8. 统一结果展示协议

### 8.1 设计原则

项目负责声明展示内容，平台负责统一渲染。

不采用项目自定义 React 页面，也不要求项目开发 HTML。

### 8.2 展示类型

**Overview：概览统计**

用于展示核心指标卡片。

例如：

- ETF 数量。
- 平均收益。
- 收益中位数。
- 正收益比例。
- 最大回撤。
- Sharpe Ratio。
- 胜率。
- 总交易次数。

**Charts：图表**

第一阶段支持：

- Line：折线图。
- Bar：柱状图。
- Scatter：散点图。

**Tables：表格**

用于展示：

- ETF 排名。
- 因子明细。
- 分组统计。
- 交易记录。
- 回测每日记录。

### 8.3 展示定义

项目声明：

- 哪些字段属于概览统计。
- 哪些数据需要绘制成图表。
- 哪些数据需要展示成表格。
- 每个字段的标题、格式和单位。
- 图表的类型、横轴和纵轴。
- 表格的列定义。

平台根据定义和运行结果自动渲染。

不要求每个项目都展示全部三类内容。

### 8.4 参数配置

项目声明参数：

- 参数名称。
- 参数类型。
- 默认值。
- 最小值和最大值。
- 步长。
- 选项。
- 必要的校验规则。

前端自动生成参数表单。

用户修改参数后创建新的 Run，不能覆盖原有运行记录。

## 9. Runtime：运行管理

### 9.1 模块定位

Runtime 负责 Research / Strategy 的实际执行。

不在普通 HTTP 请求中同步执行耗时的研究或回测任务。

### 9.2 执行流程

```text
用户点击运行
      |
创建 Run
      |
读取项目定义
      |
校验参数
      |
检查数据需求
      |
数据是否满足要求？
   /       \
  否         是
  |          |
准备数据     加载项目
  |          |
  +-----> 执行项目
              |
          调用 Quant SDK
              |
          保存结果
              |
          更新 Run 状态
              |
          Web 展示结果
```

### 9.3 Run 状态

- Pending：等待执行。
- Running：执行中。
- Success：执行成功。
- Failed：执行失败。
- Cancelled：已取消。

### 9.4 Run 记录

每次运行至少记录：

- Run ID。
- 项目 ID。
- 项目类型。
- 参数快照。
- 开始时间。
- 结束时间。
- 执行状态。
- 错误信息。
- 运行日志。
- 结果数据。
- 数据版本或实际数据快照标识。
- 项目代码版本或代码快照标识。

### 9.5 历史实验

支持：

- 查看历史 Run。
- 复制历史参数。
- 使用历史参数再次运行。
- 查看不同 Run 的结果。
- 对比不同参数下的实验结果。

## 11. 数据存储

### 11.1 技术方案

- SQLite：本地关系型数据库。
- Prisma：ORM。
- 文件系统：保存日志、运行产物及其他较大的文件。

### 11.2 数据分类

**基础数据**

- Etf
- Kline
- Valuation
- Holding
- Sw
- Link

**公共特征**

- EtfDailyFeature

**数据任务**

- DataTask
- DataTaskLog
- DataVersion

**项目运行**

- Run
- RunLog
- RunResult
- RunArtifact

以上为逻辑模型范围，具体字段和关联关系由各模块技术设计确定。

### 11.3 存储原则

- 基础行情与公共特征分开存储。
- 项目代码以文件系统为主要来源。
- Run 参数和结果需要持久化。
- 重要数据修订需要可追踪。
- 不重复保存可以直接复用的基础数据。
- 研究结果应与对应 Run 关联。

## 14. V0.1 关键架构约束

以下原则作为后续模块设计和开发的统一约束：

1. 使用 Hono，不使用 Next.js。
2. 不为每个 Research / Strategy 开发独立页面。
3. 项目通过 TypeScript 代码定义参数、数据需求、展示内容和执行逻辑。
4. 平台统一生成参数表单、概览统计、图表和表格。
5. Data Engine 统一负责数据采集、验证、更新和修复。
6. Feature Engine 统一计算每日公共特征。
7. Quant SDK 是研究项目访问量化能力的统一入口。
8. Research / Strategy 不直接修改基础数据。
9. 项目运行前检查所需数据是否准备完成。
10. 每次运行保留独立参数、代码和数据版本信息。
11. 采用本地单机架构，暂不引入分布式系统。
12. 各模块先明确边界和接口，再进行具体实现。
